# Glossary

| Term | Definition |
|------|------------|
| 301/501/701/1001 | Standard darts game variants named by their starting score; players race from that score down to exactly zero. 501 is the default competitive format. |
| Leg | One race from the starting score to zero. A match is won by taking a majority of legs (or of sets containing legs). |
| Set | A group of legs; winning a set requires winning a majority of its legs. Matches can be configured as best-of-N sets × best-of-N legs. |
| Turn (visit) | One player's throw of up to 3 darts at the board; recorded as a `TurnRecord` with three `DartData` entries. |
| Bust | Scoring more than the remaining score, reaching exactly 1, or reaching 0 without a required double — the turn is voided and the score resets to its pre-turn value. |
| Double-in / Double-out | Rule variants requiring the first (double-in) or final (double-out) scoring dart to land in a double ring (or inner bull) for it to count. |
| Checkout | The sequence of darts that finishes a leg from the current remaining score. Highest possible 3-dart checkout is 170. |
| Checkout suggestion | Optimal finishing combination (e.g. "T20, T20, D25" for 170) computed by `src/lib/game/checkout-suggestions.ts` when a player is on a finish. |
| Treble 20 / Ton 80 | Three treble-20s in one turn = 180, the maximum single-turn score; also called a "ton 80". Announced by the caller with a special clip. |
| Bull / Bullseye | Outer bull = 25 points; inner bull (double bull) = 50 points and counts as a double. |
| Caller | The audible referee voice that announces scores, busts, "game on", leg/set/match winners, etc. Implemented in `src/lib/utils/darts-caller.ts`. |
| Soundboard | Pre-generated MP3 clips in `static/audio/` — one per score (0–180) and per event, in multiple voices (default, Scotty, voice 3). Generated by `scripts/generate-soundboard.ts` via ElevenLabs. |
| Kokoro TTS | In-browser text-to-speech (`kokoro-js`, ONNX/WASM) used for dynamic phrases like player names that have no pre-generated clip. |
| Three-dart average | Career/leg statistic: average points scored per turn (3 darts). The standard measure of player strength. |
| Last-20-legs stats | Rolling statistics window over the player's 20 most recent legs, shown alongside all-time stats during and after matches. |
| MatchConfig | Config object for a match: starting score, legs per set, sets per match, double-in flag. |
| MatchState / LegState | Runtime state objects managed by `match-engine.ts`: remaining scores, legs/sets won, current thrower, current leg turns. |
| Thrower rotation | Rule (verified PDC/WDF-compliant): the player who did not start the previous leg starts the next one; same alternation applies to sets. |
| Player | A named profile in the `darts.players` table; match history and stats accumulate against it. Supports soft-delete (archive) and restore. |
| Archive | Soft-delete mechanism: players/matches are marked deleted (`deleted_at`) instead of removed, viewable under `/archive` and restorable. |
| EmailGate | Email capture/verification flow (`EmailGate.svelte`, `email.service.ts`, `verification_tokens` table) linking players to an email/account. |
| Verification token | Single-use, expiring token emailed to a player to verify ownership of an email address. |
| `darts` schema | Dedicated PostgreSQL schema holding all app tables (players, matches, legs, turns, throws, account_settings, verification_tokens) — not `public`. |
| Drizzle ORM | TypeScript-first ORM used for schema (`src/lib/db/schema.ts`), queries (`database-service.ts`), and migrations (`drizzle/`, via drizzle-kit). |
| SvelteKit / adapter-node | App framework and its Node-server build adapter; production runs as a Node server (`node build`). |
| Runes | Svelte 5 reactivity primitives ($state, $derived, …); forced project-wide in `svelte.config.js` outside node_modules. |
| OKF | Open Knowledge Format — the docs/wiki/ bundle structure used by this wiki (overview, glossary, file tree, pages). |
| te9-spec | Spec-driven development workflow (`.specs/darts-501-app/`) used to define the app before building it. |
| godaddy-cli | Vendored third-party Go CLI (`godaddy-cli/`, prebuilt `godaddy.exe`) for managing GoDaddy domains and DNS records. |
| codebase-graph | Skill that indexes the repo into a knowledge graph, stored in `.codebase-graph/`. |
